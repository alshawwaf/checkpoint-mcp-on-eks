# ADR 0005: One Helm chart driven by the server catalog

**Status:** accepted, 2026-11-01

## Decision

A single Helm chart, `charts/checkpoint-mcp`. Its `servers:` map is the 15-entry catalog. A `range` over that map renders every server identically: Deployment, Service, ExternalSecret, and a PDB when replicas ≥ 2. Enabling a server is one value, `--set servers.cloudguard-waf.enabled=true`. The chart also renders the agentgateway config from the same map, so a server and its gateway target can never drift apart.

CI enforces that `values.yaml` mirrors `chkpmcpeks/config.py` (`tests/test_catalog_parity.py`).

## Why not Kustomize

Kustomize would need one near-identical overlay or patch per server, plus a generator for the gateway config. Helm's templating fits a "same shape × N" workload, and Helm releases are what Argo CD and Flux users expect.

## Hardening built into every pod

- Pod Security Standard **restricted**, enforced on the namespace.
- Non-root, read-only root filesystem with an emptyDir `/tmp`, all capabilities dropped, `RuntimeDefault` seccomp.
- `automountServiceAccountToken: false` everywhere except the agent, which needs it for Pod Identity.
- Requests and limits on every container. HPA for the gateway and the agent. PDBs only where they cannot block node drains.
- Images referenced **by digest**, from `values-images.yaml`, generated by `chkpmcpeks build`.
- Default-deny NetworkPolicies with explicit allows.
